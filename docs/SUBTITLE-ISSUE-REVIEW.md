# 字幕遗留问题归档与每周复盘

2026-10-14 用户要求：实在解决不了的问题存档，之后每周检查新技术、模型、API 等方案。制作继续遵守 `SUBTITLE-DELIVERY-FIRST.md`；归档问题不占首版制作槽，也不将已交付的成品重新记成未完成。每周日 10:00（北京时间）复用本会话 automation-4 执行，不恢复旧两小时研究循环。

## 归档

统一索引为 `data/subtitle-studio/unresolved-issues/issues.json`。每个问题记录稳定 ID、作品/季集/版本、条目和媒体位置、当前采用的表达、未核维度、已有尝试及失败条件、原证据路径、值得重试的新条件和解决依据。复用原始失败、音频、稿件、模型清单，不复制或改写原证据。已修正的字卡或排版不重复列为未修正问题；词形、读音、主体/范围、起尾分别处理。

新一集交付时将尚未解决的具体问题追加进索引，按作品/季集/条目/维度去重。问题均为 `blocks_delivery=false`。没有可核事实时写“未知”，归档不代表已解决。首批魔王 E2 为六类问题，原版逐条待审清单继续保留。

## 每周执行

1. 读取 AGENTS 最新顶部、交付流程、统一索引、最新一次 `reviews.jsonl` 和实际新反馈。仅按引用查看必要证据，不重读聊天历史和图片集合，不重复整集分析。
2. 检索上次复盘之后的作者仓库、模型卡、正式论文和 API 官方文档；首次从归档基线日期起查。已有但上次未覆盖的可用方案也可列入，说明其新增价值。核对发布/更新日期、实际可用版本、自然日语/动画适用证据、本机资源、成本及数据去向。名称变了、排行榜好看、多个模型同意，都不足以重试。
3. 每轮最多选择两个问题，各进行一个有明确新条件的小批次。先写可证伪假设、改变的主要变量、固定输入/实现/模型版本、质量目标与停止条件；复用旧对照。默认整轮不超过45分钟，慢下载或长任务留状态，不循环等待，不挤占字幕制作和用户使用的资源。
4. 公开资料检索可直接执行。已有授权内、确有必要的免费官方本地模型和独立依赖可采用；不一次安装多个候选。不付费，不向外上传原声、视频或私有稿，不公开分享；若有价值的 API 必须付费或传出原声，先给出具体成本、数据范围与用途请用户决定。本机既有服务、下载器、驱动/WSL和其他任务保持。
5. 运行前核进程与锁，有活动或未知 owner 就不重复启动/抢锁；每次调用有明确时限，超时只结束本次自有 worker 并留错误。首次原声识别不喂 CC、技能卡、候选或第一次技能答案；保留原答和解析结果。合成控制/静音过滤/模型一致/候选评分不等于实际声音通过，所有模型观察保持 proposal。
6. 有新证据就精确记录解决了哪个维度。充分支持的字幕改进沿现有流程另存增量版本，保留成品 v1 和原稿，核受影响片段及观看出口。不覆盖停止的 production owner 共享正文，不唤醒旧大图聊天；不自动变更 accepted、默认、观看状态或生产 DB。
7. 没有新条件就维持归档，记录查过的来源、未采用原因和下一触发条件。失败分支按“问题＋输入＋实现/模型版本＋条件”去重；下一周只有实质变化才重试。按轮转顺序选择合适问题，避免长期只追最难的单点。

每轮在 `reviews.jsonl` 留一条摘要；实际实验另存私有目录，关联原始输出、耗时/资源、增益与退出原因。`issues.json` 更新对应状态，实验沿原 `iterations.jsonl` 记账。只有实质修复、有价值的新可行动方案或需要用户决定时通知；无进展安静。所有归档问题均已解决且没有新增问题时，删除本任务并报告一次；用户后来需要复盘时再启用。
