# 音频指纹自动对齐：可行性、成本与开发决定

评估日期：2026-09-30。结论：值得开发限定范围的第一版；本轮已完成可运行验证，生产播放器尚未接入。

## 开发决定
第一版做“本地同集视频 ↔ 正常可读取音轨的B站来源”的统一偏移估算。使用本机计算，不调用GPT/语音识别API。结果可靠时才应用，人工调时优先；无法读取、非同音轨或锚点不一致保留现有手动设置。巴哈姆特接入独立安排，当前尚未核验播放音轨访问，不能承诺第一版全平台覆盖。中途删OP、变速、换配音和精准正片结束切点不列入第一版自动应用范围。

需要先落实作品/季集编号核验（docs/EPISODE-IDENTITY.md），或至少已有明确核验的本地-源关联；同一OP会跨集重复，音频匹配不能成为绕过季集核验的理由。

## 本机现状
- 本地ffmpeg/ffprobe已可复用：弹弹play所带ffmpeg6.1.1；不需要解码视频画面。
- 生产Python未安装numpy/scipy/yt-dlp，现有弹幕适配器只读元数据与弹幕，不提供播放音轨。
- 研究工具隔离在data/research/audio-align：Chromaprint fpcalc1.6.1官方Windows压缩包1,816,911字节，SHA256见docs/fpcalc-research-install.json；yt-dlp2026.08.19用pip --target隔离；NumPy来自Codex已有运行时。未修改生产requirements/npm依赖或全局PATH。
- 远端音频URL只在进程内存中使用，不落盘、不打印签名URL/Cookie/token。研究结果仅含普通BV标识与数值统计；实际音轨样本在内存处理，未保存远端PCM或上传本地媒体。

## 已做的实验与实际证据
### A. 真实本地音频的可控编辑
参考音频：重骑士13的正片220秒起连续240秒。35秒窗口在40/130/180秒比较。结果不是正式跨平台成功率统计。

|处理|估算结果|判读|
|---|---|---|
|来源开头多20秒|−19.943/−20.057/−20.038秒|三点一致，最大约0.06秒误差|
|本地开头多20秒|+20.048/+20.057/+19.952秒|正负方向正确|
|来源尾部追加60秒|−0.010/0/+0.019秒|正片映射不因尾部变长而缩放|
|来源中间插入30秒|−0.010/−29.962/−29.943秒|检测到偏移跳变，第一版应拒绝统一自动偏移|
|48kbps AAC再编码、音量0.55|−0.133/−0.124/−0.105秒|编码时延约0.1秒；可用但仍须容差|
|另一部动画的35秒|最优位差率0.4434，无独立优势|应拒绝；不能仅取最小值就当匹配|

240秒解码0.403秒、指纹0.039秒、每窗口搜索约0.004秒；原始指纹7,668字节。该机器/一次运行，非普遍保证。

### B. 真正跨来源：本地23:40与B站43:59
BV1EVap6yE6B公开页面未使用登录凭据，返回3个独立音频格式。选65.679kbps音轨；HTTP Range探测206，容器总大小21,666,682字节。初次ffmpeg默认请求403，采用提取器返回的正常User-Agent/Referer后可读；生产接入须正确传递来源要求的请求头，不能只给ffmpeg一个URL。

本地全音轨解码+指纹1.878秒，原始指纹45,792字节。

|来源取样起点/长度|匹配本地位置|来源→本地偏移|平均不同位比例|样本获取+解码+指纹|
|---|---|---|---|---|
|240秒/35秒|239.943|−0.057秒|0.0524|0.632秒|
|600秒/35秒|599.981|−0.019秒|0.0177|0.587秒|
|1000秒/35秒|1000.010|+0.010秒|0.0511|0.603秒|

排除相邻5秒后其他最优位置位差率0.399–0.438，明显较差。三处正片锚点一致；证明此样本的多点对齐可行，不证明整段连续无剪辑，也未确认追加尾部的精确起点。未修改播放器偏移。

### C. 5:52 B站来源
BV1Fgau6gE3Z也可读取65.592kbps音轨，但在60/160/260秒取样后的“最优位置”位差率仍为0.396–0.431，与其他位置差别很小；三个伪偏移213/431.933/733.819秒不一致。应判为证据不足，不自动设置偏移。本轮没有确认它是剪辑、配音还是其他版本；拒绝依据为实际音频未可靠匹配，而非时长较短。

原始数值证据：docs/audio-fingerprint-benchmark.json、audio-cross-source-benchmark.json、audio-short-source-benchmark.json、audio-access-probe.json。
脚本：scripts/benchmark_audio_fingerprint.py、benchmark_cross_source_audio.py、benchmark_short_source_audio.py；全是本机忽略的研究文件，非生产模块。

## 算法选择
- Chromaprint + 分窗口原始指纹滑动比较：当前最合适的第一版。官方定位近似相同音频识别，非通用鲁棒匹配；本项目常见原配音同内容场景实际测试成立。不能将全文件压缩字符串或一个总哈希直接用于时间定位。
- 本次采用1365/11025≈0.12381秒的指纹步距，以不同位比例做代价，多点检测一致偏移，并检查其他峰的竞争程度。后续需要局部精细相关把精度提高到0.1秒级，但不能直接把粗格间隔当误差保证。
- audfprint（MIT）为备选：landmark匹配能输出offset和支持时间区间，更适合嘈杂/局部片段。默认数据库时间位数只有约6分钟，对长集会回绕；须调整且避免为每一集建立巨大默认稠密数据库。先不增加另一套生产依赖。
- Panako支持速度/音调变化，但引入Java/原生库、较多配置和AGPL依赖；本项目第一版不值得为较少见变速场景引入。
- Whisper/GPT语义对齐不是首选：成本与延迟增加，而且台词文本/“这是OP”的识别不能单独建立准确秒级映射。

## 运行成本
以下区分测量与估算，网络流量没有做进程级计量。
- API费用：该方案0，全部本机指纹计算，无需AcoustID数据库服务、付费模型或GPU。
- 本机测量：本地23:40全音轨约1.9–2.6秒；三次35秒网络样本合计约1.8–2秒；一次提取音频播放信息约1.1–1.2秒。一次新来源本例总计约5秒；网络差/授权失败会更慢，不能承诺全用户5秒。
- 网络理论下限：105秒×65.679kbps÷8≈0.86MB。容器索引、Range预读和请求开销会更多；首次工程预算按约1–5MB/来源，须实测并限流。若流不能seek、只能顺序读取，整集24分钟64–128kbps约11.5–23MB，此时应退回提示/暂不自动取样而非默默抓整视频。本例44分钟完整音频21.67MB。
- 存储：整集原始指纹约46KB；JSON存储更大，应压缩/二进制缓存。1000个同类本地指纹约46MB原始数据，不留PCM。远端样本不持久保存；缓存结果以本地文件mtime/size/音轨、来源BV+CID/分P、算法版本绑定。
- 用户等待：采用后台单并发任务，弹幕先按已有设置播放，结果到达后可提示/更新；不阻塞播放/字幕，也不每次刷新重新采样。

## 开发工时估算（个人工程判断，非已承诺排期）
|范围|估算|说明|
|---|---|---|
|离线及少量真实来源验证|约0.5–1个工程日|本轮已完成有边界的原型与正负例，尚非完整评测|
|B站统一偏移第一版|约2–4个工程日|提取器封装/来源检查、队列取消超时、缓存、人工设置优先、状态界面、真实样本校准与发布验证|
|巴哈音轨适配|另约2–5日，前提待核验|登录/地区/播放会话与音轨格式；先设半日探测，未取得正常可读音轨就停止扩展，不让其阻塞B站版本|
|中途删片头/广告的分段映射|另约3–7日|边界搜索、来源独有区段排除、时轴多段、seek与设置交互；不能复用一个offset硬套|
|变速、配音不同、严重混剪|第一版不做|先判断不可用；是否升级由真实失败样本占比决定|

集数统一身份工作另计；其研究方案尚未实施，不把该成本偷偷包含在音频估算中。

## 第一版边界与验收门槛
1. 只对已核验同集、正常能读取同语言音轨的来源运行；B站选择准确CID/分P，读取非受限音轨；巴哈弹幕通不等于音轨通。不同配音/仅共享OP不自动套值。
2. 优先匹配正片多个分散窗口，至少跨两个正片区间；避开只用OP/ED或静音。锚点数量、不同位代价、竞争峰差距、时间跨度一起判断，阈值必须用真实样本校准。本次正例约0.02–0.08、负例约0.4仅作探索，不能定义成通用百分比置信度。
3. 偏移一致才自动应用；偏移跳变/持续漂移/只有一个匹配片段返回“需要手动调整”，不改值。前端符号仍为本机时间=来源时间+offset。
4. 用户已经调过的偏移优先。结果记录依据/时间/版本，允许一键撤销、禁用自动对齐或再次计算；算法更新不覆写人工设置。
5. 建议以10–20组真实同集不同版本和至少10组负例评测：片头两边±20、尾部加长、同OP错集、静音/低音量、不同语言、B站分P错位、中段剪辑和音轨读取失败。先要求负例全部拒绝、能对齐样本多锚点人工核对误差<=0.5秒；这是一组发布门槛而非对外精度保证。
6. 不声称自动识别OP开始或尾部准确切点。统一偏移解决整体开头差；中途增删下一阶段才做分段映射。
