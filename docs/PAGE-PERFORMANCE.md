## 验收口径

本机现有服务、1440×1000 视口、服务端封面已预热、每次创建无浏览器缓存的新上下文，从导航开始计时。正文真实数据与首屏可见封面解码、绘制完成才算可用；空壳、骨架、错误提示或图片失败占位不算完成。至少五次，正常页面中位数不超过 1000ms，P95 不超过 1500ms；首页和详情继续以数百毫秒为目标。分别记录正文和封面完成时间，不能只报告接口或正文时间。缓存未命中、首次收录与外站故障另记，不与本地命中混算。

覆盖首页、全部追番、详情、季度发现、片库、管理、字幕队列及字幕库；制作档案、评审、登录、放映室也遵循同样原则，按其实际功能补用例。放映室在隔离夹具验证，禁止为测速写真实进度、租约或已看。主路径失败或超过预算必须查清并修复，不能以删除数据、隐藏功能、放宽门槛或取消真实性检查通过。

## 为什么发生退化

实际剖析发现成品功能在页面打开时逐个 HEAD 核验视频，当前规模每页约 130 次；2026-10-20 的字幕队列接入又进入详情主流程 Promise.all，令正文等待队列。此前列表快照和接口优化没有覆盖这些后增的等待。封面仍直连 lain.bgm.tv，统一懒加载，外站网络与图片大小独立拖后显示。没有证据表明曾存在的本机封面缓存被某次提交删除，不把推测写成根因。

当前成品观看按服务端精确 ID、SHA、作品季集和实时观看核验合并，消除重复 HEAD；旧服务器兼容保留。详情字幕诊断仅在正文可用后局部补充；独立 bootstrap、观看接口和清单并发。首页汇总和成品进度以批量 SQLite 快照读取，保留实时数据及文件可用性判断。

扩查还发现字幕库为每集重新构建媒体目录，已验收稿按每条中日字幕重复读相同原稿及来源规则。现改为每次请求使用单个只读数据库快照、复用媒体目录，逐个验证不同的原稿 ID；文件大小、当前绑定、验收及来源拦截仍实际核查，下一请求重新核验。页面先显示真实成品与制作进度，折叠历史随后补充并明确读取中/失败。`test_authored_performance.py` 用千条重复引用及末尾新增阻断原稿验证查询规模和门禁。

列表 CPU 剖析还核实，缺集推断每次重解析约三千个历史发布标题。现仅将「标题＋完整映射」的纯集号解析结果作有界复用；新候选或映射立即换键，黑名单、授权、播出日期与现有文件/观看仍每次读取并在缓存外判断。不能将这一纯函数缓存扩大为旧页面或旧状态缓存。`test_gaps_performance.py` 验证新候选、映射、未来集与已到料边界。

扩展检查捕获到后台候选决策在扫描同集发布历史时反复打开 SQLite 连接，与页面请求同时争用资源。单次 `SourceReview.decision` 现使用新的只读事务，原下载入口在提交前的重新决策、授权、观看及回执检查继续保留。管理状态也在一次只读投影中批量读取；投影内复用相同 show/kv 查找，但返回独立对象、事务结束即丢弃。字幕队列中文档案统计只复用原始字节到条目数的纯解析（最多 64MiB），每次仍实际读取文件、验证路径/SHA、当前来源排除与修订证据；不缓存 ready、owner 或修复结论。`test_read_projection_performance.py` 核新请求与规则变化、对象隔离、文件变动及来源拦截。

## 开发约束

- 关键读取并发，避免不必要的串行等待。可选队列、研究诊断、历史和后台统计不得阻塞主内容；异步补充保留表单、焦点与展开状态，拒绝过期响应。
- 列表、成品、续播和封面不得按条目新增数据库连接、全量磁盘扫描或网络探测；批量读取、按需字段和有界 SQL 参数，保留大小规模的查询次数回归。
- 封面经 `/covers/v1/{160|480}/...` 使用本机持久 WebP 缓存，小列表 160px、主封面 480px。首屏 eager，主封面高优先级，屏外继续 lazy；详情 HTML 预加载本作品封面。缓存位于 `data/cache/covers/`，按源 URL 和转换版本隔离，原子写入、并发去重；源地址变化使用新键。浏览器 private 长缓存及 ETag，重启复用。
- 原媒体 worker 的独立封面线程每五分钟预热目录、先处理 selected，远程下载和缩略图处理不放进 home/shows/finished-viewing 等页面数据接口。首次新图缺缓存可有外站等待，失败有界超时及冷却；不能提前声称已显示。只允许固定公开封面源与图片路径，继续原访问控制。
- 不能为速度缓存陈旧已看、续播、owner、授权或未知回执；不能省略文件真实性、中文覆盖或播放边界检查。复用同一快照和批处理，不能靠移除业务约束提速。
- 共享脚本改动同步所有 HTML 引用版本；兼容尚未加载新后端的页面。不要加入固定延时来等服务准备好。
- 调整图片转换参数或算法时，同步升级路由与文件键的转换版本，避免长缓存混用新旧字节。

## 必跑验证

CI 的现有工作流自动收集 `tests/*.test.cjs` 和 pytest。`page-performance.test.cjs` 用延迟 bootstrap/字幕队列验证主读取并发、正文不等待诊断；`cover-cache.test.cjs` 核封面分级加载及共享版本；`test_cover_cache.py` 验持久离线命中、并发、尺寸、源变更、缓存 HTTP、访问门禁。`test_home_performance.py`、`test_finished_viewing.py`、`test_read_projection_performance.py` 和列表/详情查询回归继续执行。测试只能使用临时库和假下载器。

涉及打开流程或共享功能的改动，部署验证另运行真实浏览器检查：

```powershell
# 已有 Playwright 环境可通过 PAGE_QA_PLAYWRIGHT 指向其模块目录；否则使用开发环境的 playwright。
$env:PAGE_QA_BROWSER = 'msedge'
node scripts/check_page_performance.cjs --extended
# 缓存命中必须不依赖外站封面是否在线
$env:PAGE_QA_BLOCK_EXTERNAL_IMAGES = '1'
node scripts/check_page_performance.cjs
Remove-Item Env:PAGE_QA_BLOCK_EXTERNAL_IMAGES
```

默认五次/页面，`PAGE_QA_SHOWS` 指定两个已收录详情 ID，`PAGE_QA_BASE` 仅接受本机服务；`PAGE_QA_OUT` 可指定私有 JSON 报告，默认 `data/diagnostics/page-performance-latest.json`。脚本拒绝所有写请求，检查真实内容、可见封面、JS 错误与性能预算；失败非零退出。它不能替代放映室隔离交互测试。性能工作必须保存前后结果、运行版本和视口。

报告同时记录浏览器/版本、导航及资源的 DNS/连接/请求/首字节阶段和主线程长任务。2026-11-01 的 Chrome/Edge 扩展实测已达到数百毫秒的页面中位数，但仍捕获到秒级长尾，不能声称九类页面的 P95 全部达标。部分慢样本在 HTTP 请求发出前排队数秒；同期独立本机脚本请求可在几十毫秒内返回，另有少量同步停顿。浏览器 trace 也捕获到窗口管理、配置写入与布局长任务。这些证据不能证明所有长尾都来自同一原因，不能直接把外部争用说成已根治，也不能通过放宽预算、只选快样本或连续重启来报成功。交接保留 `data/diagnostics/cover-performance-20261101/` 的全部原始报告，后续针对仍超预算的样本继续定位。
