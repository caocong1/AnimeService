# 弹幕跨版本时间对齐（2026-09-29）
> 2026-09-30更新：已完成B站公开音轨的真实多点指纹实验，并决定开发限定范围第一版。生产尚未接入；巴哈音轨仍待核验。实测数值、成本与阶段边界以[音频对齐评估](AUDIO-ALIGNMENT-FEASIBILITY.md)为准。下文“未验证音轨/工具”是2026-09-29历史状态；来源选择持久化已在后续上线。

## 已实现

每份本机视频、每个弹幕来源独立保存 offset（秒），在当前浏览器 localStorage 保存；来源使用稳定URL的SHA-256身份，不使用会因重启变化的临时source_key。此版不跨设备同步、不保存手动来源选择，仅保存调时参数，再选同来源即可恢复。

映射：本机显示时间 = 来源弹幕时间 + 来源偏移 + 全部微调。

- 本机比来源开头多20秒：来源偏移 +20（弹幕延后）。
- 来源比本机开头多20秒：来源偏移 -20（弹幕提前）。
- 支持0.5秒输入、提前/延后1秒、归零；源时间保持不变，切换偏移不会累积误差。
- 后端同时返回每来源原始弹幕及兼容的合并结果；前端先调整各来源，再按时间/文本/模式去重，避免在调时前丢掉另一个来源的同文弹幕。
- 调整后落在0之前或本机视频结束之后的弹幕不播放，不将负数挤到第0秒。
- 可选“来源正片结束位置”按来源原始时间裁掉尾部拼接弹幕；不改媒体、不按总时长比例缩放。

用户补充覆盖此前的过强推断：B站总长43:59、本机23:40不构成正片不匹配的证据。UP主可能仅追加尾部，前段音画可以完全相同。当前未做音画核验，不能从时长推断尾部内容或对齐值。此前两个BV接口返回0条与时长问题分别处理。

## 自动对齐的可行方案（尚未实现）

目标应是“相同内容对应的时间映射”，而不只是语义识别“这是OP”。单个OP起点无法识别中途删减；同一OP在别集也会重复，不能作为作品/集数身份证据。

1. 先核验作品与集数。取本机与来源中合法可访问的音轨片段，优先本地计算音频指纹，多点比较；匹配窗口应覆盖开头、OP后和正片中段，不能只有OP歌曲。
2. 多窗口偏移一致时，提出统一偏移建议；若偏移在OP/广告处跳变，提出分段映射，并排除来源独有区段弹幕。非连续剪辑不要强行整体对齐。
3. 用低频画面指纹交叉验证；必要时用语音或已有字幕的对应台词辅助。GPT可辅助理解抽帧中的片头/标题卡和匹配证据，不把语义猜测直接作为秒级时间轴。
4. 尾部追加内容保持前段映射不变，只识别正片覆盖区间；无法确定尾部切点时保留手动结束位置。变速、配音、镜像、裁切、反复片段等需单独检测，不能用总时长比充当播放速度。
5. 先展示建议偏移、匹配片段、置信依据供确认；用户手动修正优先。自动应用阈值需用真实多源样本校准，不能凭固定“置信度90%”数字宣称可靠。

当前能力差距：本机已有ffprobe/ffmpeg用于字幕提取，但适配器仅连接远端搜索/分集/弹幕，尚无受支持的跨平台音轨读取链路，也未验证音频指纹工具安装或精度。B站/巴哈视频可能需要登录、地区授权或受保护播放；只处理正常可访问的内容，不把字幕/弹幕访问成功视作能获取音轨。此轮没有抓取远端正片、安装模型或上传本机视频。

建议下一阶段：用两份用户可访问的同集视频做离线原型，覆盖开头±20秒、OP中段增删、尾部加长、错误集数、字幕/水印差异；验证多个非OP锚点后再连接来源播放接口。仅有弹幕时间和文字时不能可靠恢复真实音画映射。

技术依据：Chromaprint官方说明定位为近乎相同音频的指纹识别，而非通用鲁棒音频匹配；raw fingerprint可用于比较，但还需实现滑动匹配和多锚点一致性检测。https://github.com/acoustid/chromaprint/blob/master/README.md 、https://github.com/acoustid/chromaprint/blob/master/src/chromaprint.h 。此处为设计建议，不是已完成自动对齐的声明。
