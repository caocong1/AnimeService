# Bangumi 开放平台与个人记录同步

Bangumi 的公开 API 可以作为本系统的作品资料来源，也能保存个人收藏和逐集观看记录。当前接入采用本系统到 Bangumi 的单向同步；本地个人意愿、观看证据、下载授权继续独立。账号连接和启用入口为本机 `/manage#bangumi`。

## 平台能力与用途

| 能力 | 对本系统的用途 | 当前处理 |
| --- | --- | --- |
| 作品搜索、分类浏览、详情、封面、评分和标签 | 查找 TV、WEB、剧场版、OVA，补齐别名与集数 | 复用现有目录与搜索；普通资料更新保持个人状态 |
| 章节详情与稳定章节 ID | 对应具体已看集，区分季内编号 `ep` 和累计排序 `sort` | 新增完整章节缓存；修正按实际返回条数分页，拒绝重复或提前结束 |
| 收藏状态与章节收藏 | 同步想看、在看、看过、搁置、抛弃及逐集已看 | 已实现持久队列、回读确认、断网补发、冲突处理 |
| 个人评分、短评、标签、隐私 | 保持个人评价和收藏可见性 | 评分和短评可选择同步；现有标签与隐私保留，新收藏缺省私密 |
| 关联作品、角色、制作人员、维基修订和目录 | 后续可补续作导航、制作阵容、资料变动提示、个人片单 | 本轮研究范围，未新增这些页面或自动行为 |

上述公开端点以 `https://api.bgm.tv/v0/` 为入口；旧 `/calendar` 可提供星期放送目录，但不能证明实际发布、资源到达或某集观看完成。搜索接口在官方规格中标为实验性，需要验证分页和返回字段。公开 API 与新网站依赖的 Cookie 私有 API 是不同接口；本项目继续使用公开 API。[官方 API 规格](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)、[旧 calendar 规格](https://github.com/bangumi/api/blob/master/open-api/api.yml)、[公开与私有 API 说明](https://github.com/bangumi/dev-docs/blob/master/README.md)。

## 授权与账号连接

官方提供个人 Access Token 生成入口，适合单用户本机部署。另一条路径为注册 OAuth 应用，使用授权码及 refresh token，需 App ID、App Secret 和已登记的回调地址。当前实现采用个人令牌；令牌到期需要重新连接，尚未实现 OAuth 自动续期。[令牌入口与官方说明](https://github.com/bangumi/api/blob/master/open-api/api.yml)、[OAuth 授权文档](https://github.com/bangumi/api/blob/master/docs-raw/How-to-Auth.md)。

1. 在家中电脑打开后台的 **Bangumi 同步**。
2. 从页面链接进入 [Bangumi 官方令牌页面](https://next.bgm.tv/demo/access-token)，登录并生成令牌。
3. 仅在本机密码框粘贴，点击 **核验并连接账号**。系统通过 `/v0/me` 确认账号。
4. 选择新收藏是否私密，以及是否同步个人评分和短评，勾选 **自动同步个人列表** 并保存。

令牌使用 Authorization Bearer 请求头，仅在内存及 Windows 当前用户 DPAPI 加密文件 `data/bangumi-auth.bin` 中使用。不会写入 SQLite、响应、页面回显、日志或 URL。请求固定官方 HTTPS 主机，不跟随重定向。User-Agent 含用户标识和应用名；该标识是请求方身份，不是 OAuth 客户端注册信息。[官方 User-Agent 建议](https://github.com/bangumi/api/blob/master/docs-raw/user%20agent.md)。

## 同步语义

| 本地状态 | Bangumi 收藏 |
| --- | --- |
| 想看 `wish` | 想看 `1` |
| 试看 `trial`、在追 `watching` | 在看 `3` |
| 暂搁 `paused` | 搁置 `4` |
| 弃番 `dropped` | 抛弃 `5` |
| 看完 `completed` | 看过 `2` |

仅 `selected=1` 的个人列表参与同步，包括其中的历史已看和弃番；不限于多版本评审的新番范围。目录默认 wish、季度授权、自动下载或文件存在都不会进入收藏同步。取消个人选择只停止后续同步，不删除 Bangumi 收藏。同步不会改动本地状态，也不会执行下载、恢复授权、清理或媒体操作。

分集使用 `watches.finished=1`；手动标记和已核验的弹弹play LastWatched 都可同步。仅打开播放器、LastPlay、退出位置和下载完成不是已看。官方动画进度要通过章节 ID 更新，不写仅供书籍使用的 `ep_status`。本地显式手动取消已看，只撤回本系统已经管理的章节；Bangumi 单独标记、而本地没有管理过的章节保留。[收藏及章节规范](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)。

章节优先使用已独立核验、绑定作品/章节ID/ep/sort签名的同步编号规则；没有专用证据时根据已保存的 `airing_offset`，否则使用 Bangumi `ep`；缺少季内编号时，仅允许已核验的排序偏移或从 1 连续编号。`airing_offset` 的三种状态含义不同：缺省（保存映射时未提供，2026-10 起不再自动写成 0）表示看板与同步都用 Bangumi 自身的 sort→ep 偏移；非零值两边都直接使用；显式 0 目前同步按 sort 直接编号、看板按缺省处理，两边可能不一致，统一前先用 `python scripts/airing_numbering_diff.py <数据库副本>` 只读列出不一致的作品，再决定逐作品证明或改语义。绝不使用下载标题的 `mapping.offset` 去推算 Bangumi 章节。归属、ID、编号有歧义或缺少已看章节时显示“需要核验”，其余本地记录保持。只读实测 JOJO 639938 的排序 2 对应季内第 1 集、章节 ID 1663677；该观察不新增任何下载授权。

首次启用，以本地明确状态更新对应收藏。已有评分和短评默认保留；用户勾选后才用本地非空内容更新，已由本系统同步过的评分/短评随后清空也同步。弃番原因不上传。新收藏私密选项只影响新建条目，不改既有可见性。

## 可靠性与实时范围

SQLite 触发器在本地状态或已看标记变更的同一事务中递增队列 revision。普通资料和时间戳/位置刷新不会制造观看变更。后台独立线程每 5 秒检查、每轮最多 4 部，API 请求间隔至少 0.3 秒；首次批量同步、上游延迟和重试会影响实际完成时间，不能承诺恒定数秒完成。弹弹play 原有本机历史读取每 60 秒，随后进入相同队列。电脑、服务和网络必须可用。

每次写入前回读，写入后再核对。生产收藏/章节写入可能返回 HTTP 202；只视为已受理，仍需远端回读一致才记成功。提交意图先持久保存，处理“服务器已接受但响应丢失”；重启后先回读，避免无意义的重复写入，也保留用户在超时之后取消已看的修正。队列按最新 revision 合并，新状态不会被旧结果误记为已同步。429 遵守 Retry-After（上限一天）；单部作品的网络失败按 30 秒翻倍、内置上限 1,920 秒（取与 Retry-After 的较大者，所以实际可能更长）；401/403 暂停等待重新授权。只有凭据读取失败或账号不匹配才标记"需要重新连接"，数据库忙、客户端构造失败等其它异常只按 1 分钟翻倍至 1 小时退避并保留队列。

回执按账号 ID 隔离。已由本系统管理的字段或章节被外部修改时提示冲突，普通重试不会覆盖；用户可打开 Bangumi 核对后，逐作品确认“使用本地记录”。不同账号须先断开再连接，重新连接不会自动启用。远端条目更新时间不作为冲突依据，因为官方指出某些修改不更新该时间。当前没有实施 Bangumi 到本地的反向同步或远端变更通知。[更新时间限制](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)。

## 实施与验证

实现文件为 `anime/bangumi.py`、`bangumi_auth.py`、`bangumi_sync.py`，持久表和触发器在 `anime/db.py`，后台入口在 `static/bangumi-sync.js`。现有 `Catalog.details` 保留完整章节 ID 缓存，章节分页失败保持原分集数据；通用网络层使用新的 User-Agent。

2026-10-07 首轮未授权阶段：全套 424 项临时数据库/假下载器 Python 测试通过（包含同期其它功能测试），其中本轮 Bangumi 同步专项 33 项；JavaScript 语法与 diff 检查通过。实际本机未授权页面、1440/390/320 宽度及已连接/冲突的隔离 fixture 共 5 张截图无页面横向溢出或脚本错误。4 次页面 POST 均被 Playwright 拦截，没向生产连接测试账号或写入 Bangumi。

首轮未授权阶段，生产新入口有 90 部个人作品、565 条已看记录；连接账号和自动同步均未开启，回执数 0。从本轮重载前备份基线核对，shows 保护字段、watches 和下载策略一致。后台普通季度任务期间新增 542007 第 1 集 pending 关联，仍为 selected=0/wish、原授权及 auto_download；它不参与 Bangumi 同步，本同步模块没有媒体/下载台账写入。证据 `docs/bangumi-sync-state-proof.json`。实际账号的首次远端写入和端到端同步，要在用户完成本机授权后核验；隔离测试不冒充实际账号成功。

后续适合继续做的优化：关联作品的续季导航、按角色/制作人员检索、展示评分人数以解释评分、基于维基修订检查资料变动。收藏分析或推荐只提供信息，不自动更改追番或下载授权；真正双向同步需另行确定冲突优先级。
